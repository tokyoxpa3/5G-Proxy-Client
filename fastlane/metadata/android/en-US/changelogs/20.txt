- Fix: a DNS query carried over TCP (remote DNS enabled, with the query itself sent through the tunnel) was never released. The connection record and its buffer stayed allocated, and the session counter only ever went up. After 512 of them the client would refuse every new TCP connection — DNS and ping still worked, everything else was dead, and restarting the tunnel brought it back. The session now releases itself as soon as the answer has been written back, and a regression test asserts the session count returns to its pre-connection level (it fails without the fix)
- Fix: when a protected socket could not be set up, the socket that had already been created was left open. A connect timeout to the SOCKS5 server was the common case, and repeated failures leaked one file descriptor each. The socket is now closed on every failure path
